# The subset of requirements.txt that rag.py's HTTP API actually imports
# at serve time -- across all 12 local modules Dockerfile.serve copies, not
# just the original five. Deliberately excludes spacy, rapidfuzz and
# openpyxl -- those belong to the extraction/review pipeline (main.py,
# subject_specificity.py, review_cli.py), not the served API, and spacy's
# en_core_web_sm download alone adds real image size and build time that a
# free-tier host's build minutes should not pay for.
#
# Keep in sync with requirements.txt by hand -- there is no tooling that
# enforces this split, so if the API gains a new import, add it here too.
#
# torch and transformers are NOT here, and are not missing either: they moved
# to requirements-translation.txt, which Dockerfile.serve now installs on top
# of this file so torch can come from the CPU wheel index. Keeping them out
# of this list means a host that only serves English retrieval still does not
# pay for them. See Dockerfile.serve and KNOWN_LIMITATIONS 29.
requests
# Translates Bangla/Hindi questions and answers (rag.py google_translate).
deep-translator
neo4j
python-dotenv
pdfplumber
wordninja
# Required by subject_specificity.py, via main.py. Needs the
# en_core_web_sm model too -- Dockerfile.serve downloads it.
spacy
